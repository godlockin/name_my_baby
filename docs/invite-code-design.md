# AI 起名助手 - 邀请码系统设计

**版本：** v1.0
**日期：** 2026-03-17

---

## 1. 邀请码获取方式

### 1.1 分享得邀请码（免费用户）
```
用户完成一次起名 → 生成分享海报 → 好友扫码注册 → 双方获得邀请码
```

### 1.2 付费赠送（付费用户）
```
用户购买付费版 → 赠送 3 个邀请码（可分享给朋友）
```

### 1.3 阶梯奖励
| 邀请人数 | 奖励 |
|----------|------|
| 1 人 | 1 个邀请码 |
| 3 人 | 2 个邀请码 + 9 折券 |
| 5 人 | 免费无限卡（7 天） |
| 10 人 | 免费无限卡（30 天） |

---

## 2. 邀请码权益

**1 个邀请码 = 1 次完整生成体验**

包含：
- 5-8 个完整方案
- 完整谐音检查（含方言、中英文）
- 详细分析（诗词出处、历史典故、五行分析）
- 英文名推荐 + 典故
- 收藏/对比功能
- Pin + 定向重新生成
- 多子女名字关联优化

**有效期：** 30 天

---

## 3. 邀请码格式

```
格式：[6 位大写字母 + 数字]
示例：AB3X9K、NAME26、BABY88

生成规则：
- 前 2 位：随机大写字母
- 中间 2 位：随机数字
- 后 2 位：随机大写字母
- 总计：36^4 × 100 ≈ 1.6 亿种组合
```

## 5. 防刷机制

| 手段 | 实现方式 | 说明 |
|------|----------|------|
| **Device ID 限制** | 每个设备只能用 1 个邀请码 | 防止同一设备反复注册 |
| **手机号验证** | 使用邀请码需绑定手机号 | 增加刷单成本 |
| **微信授权** | 小程序端需微信授权 | 微信天然防刷 |
| **IP 频率限制** | 同一 IP 短时多次使用触发审核 | 防止批量注册 |
| **邀请码有效期** | 30 天过期 | 过期不可用 |
| **黑名单机制** | 异常设备/手机号拉黑 | 事后处理 |

## 6. 禁止交易设计

**核心原则：邀请码与使用者强绑定，不可转移**

### 6.1 绑定机制
```
邀请码使用流程：
1. 用户输入邀请码（或扫码自动填入）
2. 系统验证邀请码有效
3. 系统记录绑定关系：
   - 邀请码 → 使用者微信 ID / 手机号
   - 邀请码 → 使用者 Device ID
   - 邀请码 → 状态：已使用
4. 解锁权益

尝试二次使用：
- 另一用户输入同一邀请码 → 返回「此邀请码已使用」
- 拒绝
```

### 6.2 数据存储
```json
{
  "invite_code": "AB3X9K",
  "status": "used",
  "creator_user_id": "user_123",
  "used_by": {
    "wechat_id": "wx_xxx",
    "phone": "138****5678",
    "device_id": "device_yyy"
  },
  "created_at": "2026-03-17T10:00:00Z",
  "used_at": "2026-03-17T12:00:00Z",
  "expires_at": "2026-04-16T10:00:00Z"
}
```

### 6.3 为什么无法交易？
1. **一次性使用** - 使用后立即失效，下一个人无法使用
2. **强绑定** - 使用时绑定当前用户，无法转给他人
3. **权益即时发放** - 使用后权益直接发到当前账户，无法转移

## 7. 不可叠加设计

**原则：一次只能用 1 个邀请码**

```
用户已有 1 个邀请码，又想用第 2 个？
→ 系统提示：「您有待使用的邀请码，请先使用当前邀请码」

用户用了邀请码，又想叠加优惠券？
→ 系统提示：「邀请码权益不可与其他优惠叠加」
```

**简化逻辑：**
- 邀请码 = 1 次完整生成
- 没有「更多权益」需要叠加
- 用户要么用邀请码，要么直接付费

|------|--------|------|
| 邀请码发放数 | - | 总共发放了多少邀请码 |
| 邀请码使用率 | > 60% | 发放后有多少被使用 |

| 人均邀请数 | > 1.5 | 平均每个用户邀请多少人 |
| 作弊率 | < 5% | 异常邀请占比 |
